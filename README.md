# Oracle → Elasticsearch comparison pipeline

Pulls rows from Oracle, shapes them into the same field-set as
Elasticsearch documents, diffs both sides, and (optionally) writes the
diffs back into ES.

## How to add a new index


Adding a new index requires only files inside one folder:

```
settings/indexes/<index_name>/
├── config.yaml          # MODE / PK / BANCH_VALUE / INDEX_NAME / part list
├── sql/
│   └── query.sql        # Oracle SELECT (id_range/time mode) — or omit if using parts/
├── mapping.csv          # filed_orcal,filed_es,funciton_lambda
├── helpers.py           # class Adapter(IndexAdapter) — overrides + lambdas
└── schema.csv           # auto-generated by `python -m apply_changes.fetch_schemas`
```

Multi-template indexes (e.g. `playerbonus`) replace `sql/query.sql` +
`mapping.csv` with a `parts/` subdir, one folder per template:

```
settings/indexes/<index_name>/
├── config.yaml          # parts: [...]
├── parts/
│   ├── template_a/
│   │   ├── sql.sql
│   │   └── mapping.csv
│   └── template_b/
│       ├── sql.sql
│       └── mapping.csv
└── helpers.py
```

Then add a small reference to `settings/events.yaml`:

```yaml
NEW_EVENT:
  IS_RUNNING: true
  index_config: indexes/<index_name>/config.yaml
  START_TIME: '2026-01-01 00:00:00'   # only for time / time_union modes
  END_TIME:   '2026-01-02 00:00:00'
  FILED_THAT_RUN: id,name,createdDate  # comma-separated; '' = all
```

That's it. **No edits required to** `main.py`, `apply_changes.py`,
`core/*.py`, or any of the connector modules. The pipeline discovers
the new index via the filesystem.

### What goes in `helpers.py`

Minimum:

```python
from core.adapter import IndexAdapter

class Adapter(IndexAdapter):
    INDEX_NAME = "my_index"
```

Optional overrides:

| Method | When to override |
|--------|------------------|
| `lambdas()` | Index has its own value-transform functions referenced by `funciton_lambda` column in `mapping.csv`. Returns `{name -> callable}`. |
| `field_kind_overrides()` | ES mapping diverges from the lambda-derived kind for some fields (e.g. ES=keyword but lambda emits int → `"int_str"`). |
| `before_apply(doc)` | Mutate every doc before send to ES (e.g. stamp `updateDate=now()`). Must return new dict. |
| `coerce_for_es(field, value)` | Custom CSV-string → ES-typed coercion. Default uses `core.coerce.coerce` against bound field types. |
| `validate(doc)` | Per-doc validation rules. Default returns `[]`. |

Generic value converters (`convert_int_to_string`, `convert_time_to_string`, …)
live in `settings/common_lambdas.py` and are auto-available — index helpers
only need to define index-specific ones.

## What the project does

For each event in `settings/events.yaml`:

1. Read Oracle in time- or id-windowed batches.
2. Shape rows into ES-keyed columns using `mapping.csv` + adapter lambdas.
3. Pull the matching ES window/IDs.
4. Compare per-PK, field-by-field; emit `out/<EVENT>/<env>/changes/`:
   - `changes_<stamp>.{csv,parquet}` — field-level diffs.
   - `missing_in_es_<stamp>.{csv,parquet}` — full Oracle rows not present in ES.
5. Local files are the source of truth. **Nothing heavy is written to
   Postgres** — only small observability rows (timing, counts, status).
6. `apply_changes` reads pending rows from local Parquet via DuckDB by
   default (`--source duckdb`) and writes back to ES with adapter-driven
   type coercion + per-doc `before_apply` hook.

## How the pipeline works

```
Oracle SELECT  ─┐                       ┌─→ changes_*.{csv,parquet}
                │                       │
                ├─→ transform (mapping) ┼─→ missing_in_es_*.{csv,parquet}
                │                       │
ES query       ─┴─→ compare (per PK) ──┘
                                         └─→ DuckDB views over local files

apply_changes (default --source duckdb):
  v_changes / v_missing → coerce_for_es → before_apply → ES

PostgreSQL (sidecar, best-effort, never blocks):
  pipeline_run_summary, connection_log, query_log, batch_log
```

## How to run

Install deps. Two options:

**Poetry (recommended):**

```bash
poetry install              # creates .venv and installs from pyproject.toml
poetry run python main.py    # run inside the managed venv
poetry shell                 # or drop into the venv shell
```

If you don't have `poetry.lock` yet, generate it once with `poetry lock`
(needs the `poetry` CLI on `PATH`; `pipx install poetry` is the easiest
install). The lockfile is what guarantees reproducible installs across
machines — commit it after the first `poetry lock`.

**pip:**

```bash
pip install -r requirements.txt
```

Run the diff pipeline (every event with `IS_RUNNING: true`):

```bash
python main.py
# or
poetry run python main.py
# or
poetry run pipeline                    # via [tool.poetry.scripts]
```

Apply diffs back to ES for one event:

```bash
python -m apply_changes.apply_changes --event PLAYERBONUS --env prod --mode both
# or:  poetry run apply-changes --event PLAYERBONUS --env prod --mode both
#
# --mode    changes | missing | both
# --env     stage | prod
# --dry     print what would happen, no writes
# --source  duckdb (default) | pg | csv | auto
#           duckdb : read pending diffs from local Parquet via DuckDB
#           pg     : legacy fallback — read from pipeline_changes
#           csv    : read changes_*.csv files directly
#           auto   : try pg → duckdb → csv
# --no-refresh  skip pulling fresh ES schema before validation
```

Refresh ES schema CSVs (per index, from prod):

```bash
python -m apply_changes.fetch_schemas             # all known indexes
python -m apply_changes.fetch_schemas playerbonus  # one
# or: poetry run fetch-schemas
```

Streamlit settings editor / runner:

```bash
streamlit run app.py
```

## Configure `.env`

Copy `.env.example` to `.env` and fill in:

```ini
# Oracle source
ORACLE_USERNAME=...
ORACLE_PASSWORD=...
ORACLE_DB_HOST=...
ORACLE_SERVICE_NAME=...
ORACLE_PORT=1521

# Elasticsearch — at least one of stage/prod required
ES_URL_STAGE=https://stage.es.example.com
ES_URL_PRODE=https://prod.es.example.com
ES_USER=...
ES_PASS=...
ES_VERIFY=false

# Postgres mirror (required for apply_changes pending-rows path)
PG_HOST=...
PG_DB=...
PG_USER=...
PG_PASSWORD=...
```

Pipeline knobs:

| Var | Effect |
|-----|--------|
| `PIPELINE_WORKERS` | Number of worker processes (default 4). |
| `PIPELINE_SAVE_FULL_CSV` | `1` = also write the full Oracle/ES CSVs per batch (debug). |
| `PIPELINE_VERBOSE` | `1` = per-batch row counts on stdout. |
| `PIPELINE_DIFF_MODE` | `changes` / `missing` / `both` — what the pipeline writes. |
| `PIPELINE_SKIP_PG_SYNC` | `1` = don't mirror outputs to Postgres after a run. |
| `APPLY_BATCH_SIZE` | Bulk batch size in apply_changes (default 1000). |

The full set is in `.env.example`.

## stage vs prod

- **stage**: `ES_URL_STAGE` only; no auth assumed. Used for testing apply
  flow against a non-production cluster.
- **prod**: `ES_URL_PRODE` + `ES_USER` + `ES_PASS` required. The schema
  refresh path (`fetch_schemas`, `--no-refresh` not set in `apply_changes`)
  always pulls from **prod** regardless of `--env`, because prod is the
  authoritative ES mapping source.

Per-event default env lives in each index's `config.yaml` under
`ES_ENV: stage|prod`. The CLI `--env` flag overrides at apply time.
